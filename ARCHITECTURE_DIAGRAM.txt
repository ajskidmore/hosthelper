DATA FLOW EXAMPLE: CREATE A PROPERTY
================================================================================

1. User clicks "Add Property" button
   └─> PropertyDialog opens

2. User fills form and clicks Save
   └─> handleSaveProperty() called in Properties.tsx

3. Component calls useProperties().addProperty(propertyData)
   └─> Custom hook fires addDocument(data)

4. addDocument() calls Firebase SDK
   └─> await addDoc(collection(db, 'properties'), {...data, createdAt, updatedAt})

5. Firebase writes to Firestore
   └─> Database executes: INSERT INTO properties VALUES (...)

6. Real-time listener (useFirestoreQuery) detects change
   └─> onSnapshot callback fires automatically

7. Component state updates
   └─> setDocuments([...newData])

8. UI re-renders with new property
   └─> Component reads from properties state and displays it

Entire flow: Form → Hook → Firebase SDK → Firestore → Listener → State → UI

All happens in real-time without polling!

AUTHENTICATION FLOW
================================================================================

LOGIN:
  User enters email/password
    ↓
  Login.tsx calls useAuth().signIn(email, password)
    ↓
  AuthContext calls signInWithEmailAndPassword(auth, email, password)
    ↓
  Firebase Auth verifies credentials
    ↓
  onAuthStateChanged listener triggers (in AuthContext useEffect)
    ↓
  fetchUserData() retrieves user document from Firestore
    ↓
  setUser(userData) updates Context state
    ↓
  Browser persists user (browserLocalPersistence)
    ↓
  App navigates to dashboard (ProtectedRoute allows access)

LOGOUT:
  User clicks logout
    ↓
  signOut() called
    ↓
  Firebase clears session
    ↓
  onAuthStateChanged listener triggers with null user
    ↓
  setUser(null) clears Context
    ↓
  App redirects to /login
    ↓
  New session requires login again

GOOGLE OAUTH:
  User clicks "Sign in with Google"
    ↓
  signInWithPopup(auth, googleProvider) opens popup
    ↓
  User selects/authenticates with Google account
    ↓
  Firebase receives OAuth token
    ↓
  Check if user document exists in Firestore
    ├─ If NEW: Create user document with default roles
    └─ If EXISTS: Load existing roles
    ↓
  setUser() with loaded/created data
    ↓
  App navigates to dashboard

================================================================================
ROLE SWITCHING FLOW
================================================================================

User has roles: ['owner', 'provider']
Current role: 'owner'

1. User clicks "Switch to Provider" button
   └─> calls useAuth().switchRole('provider')

2. switchRole() updates Firestore
   └─> await setDoc(doc(db, 'users', user.id), {currentRole: 'provider'})

3. Local state updates
   └─> setUser({...user, currentRole: 'provider'})

4. UI responds to changed currentRole
   └─> Navigation shows provider pages instead of owner pages
   └─> Data hooks show provider-specific data (available jobs instead of properties)
   └─> Dashboard changes to show provider stats (earnings, active jobs)

5. Data queries change based on role:
   - Owner: See properties, bookings they own
   - Provider: See posted public jobs, tasks assigned to them

All done without page reload - smooth role switching!
